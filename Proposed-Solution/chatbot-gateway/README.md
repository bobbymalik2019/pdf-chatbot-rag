# chatbot Node.js gateway

Express 5 gateway for the previously provided Folio React frontend and your Python API. Requires Node.js 22.12+. Streams requests/responses rather than parsing/rebuilding uploads. Includes static React hosting, API proxy, request IDs, basic security headers, non-sensitive request logs, timeout/error handling, and shutdown handling.

## Folder layout

```text
workspace/
  chatbot/
    package.json
    dist/               # generated by frontend npm run build
    chatbot-gateway/
    package.json
    .env
    src/server.js
```

## Start

In the React project, set `.env`:

```env
VITE_API_MODE=live
VITE_API_BASE_URL=/api
```

Then run `npm install` and `npm run build` in the React project. Frontend Vite variables are build-time settings: rebuild after changing them.

In this gateway directory:

```sh
npm install
cp .env.example .env
npm start
```

Windows Command Prompt: `copy .env.example .env`. PowerShell: `Copy-Item .env.example .env`.

Start your existing Python service separately. Edit the gateway `.env` for its real address. Open http://127.0.0.1:3000 (use the same hostname consistently for cookies). The gateway does not launch Python.

## Endpoint mapping

Default: `PYTHON_API_BASE_URL=http://127.0.0.1:8000`, empty `PYTHON_API_PREFIX`.

| Browser/Node                                  | Python                                    |
| --------------------------------------------- | ----------------------------------------- |
| GET /api/sessions                             | GET /sessions                             |
| GET /api/sessions/:id                         | GET /sessions/:id                         |
| POST /api/sessions                            | POST /sessions                            |
| GET /api/documents/:id/file                   | GET /documents/:id/file                   |
| POST /api/sessions/:id/messages               | POST /sessions/:id/messages               |
| PUT /api/sessions/:sid/messages/:mid/feedback | PUT /sessions/:sid/messages/:mid/feedback |

Set `PYTHON_API_PREFIX=/api` if Python expects `/api/sessions`. Query strings pass through. This is a transparent proxy: it does not translate your Python response schemas into the frontend schema. If your existing API differs, update `src/api.js` in the frontend or add explicit Node adapter routes.

## Development

Run gateway `npm run dev`. Copy the contents of `vite.config.example.js` into the React project's `vite.config.js`, then run the React project's `npm run dev`. Browser -> Vite -> Node -> Python. Vite proxy is only for development. Production Node serves the built React dist directly.

## Authentication and production boundaries

This is integration scaffolding, NOT a complete production authentication service.

- Cookie and Authorization headers are forwarded. Python MUST verify user identity and authorize ownership of every session, file, message, and feedback record. No client-supplied user ID should establish identity. React currently sends cookie credentials, not custom bearer tokens.
- If Node owns login instead, add real session middleware and a verified, scoped Node-to-Python identity mechanism BEFORE the proxy. Do not merely forward a browser user ID or add a shared all-access service token.
- Python must issue cookies usable on the public gateway origin. Configure host-only cookies (omit internal Python Domain), appropriate cookie Path, Secure/HttpOnly/SameSite attributes and HTTPS. This starter does not rewrite cookies. Browser iframe PDF previews need cookie-based access or an adapted signed URL.
- Implement CSRF protection for cookie-authenticated writes in your authentication layer. Same-origin routing alone is not CSRF protection. No permissive CORS middleware is included.
- The proxy exposes all Python paths under the chosen prefix. Restrict this to intended public API routes before production, and keep admin/internal Python endpoints off the exposed service/prefix.
- Set rate limits, total upload limits and file validation in Python and/or your trusted ingress. Uploads are streamed and are NOT size-limited by this Node starter. Validate PDF contents, encrypted files, malware controls and resource budgets server-side. Enforce ratings 1–10, with required trimmed comments for 1–6, in Python.
- Bind defaults to loopback. For containers, set HOST=0.0.0.0 and put a trusted HTTPS ingress ahead of it. TRUST_PROXY=true trusts one proxy hop; configure it to match the actual network topology and prevent untrusted direct access. Forwarded client identity is deliberately not passed to Python.
- Configure ingress and Python timeouts consistently. Gateway default upstream timeout is 180 seconds. A timeout does not prove a write failed; implement idempotency for upload/message creation before automated retries.
- Upstream non-2xx responses pass through unchanged; connection failures return 502, recognized timeout errors return 504. No automatic retries. /healthz indicates Node liveness only, not Python readiness.
- PDF Range headers and response bytes pass through. No body parsers/compression/response interceptors run ahead of the proxy. Whether PDFs support range requests and chat supports streaming depends on Python and ingress. Current React client expects complete JSON chat responses, not SSE.
- Requests are logged without payloads, URLs/query strings, cookies or tokens. Do not log document contents or feedback without a privacy policy. Add monitoring, secret management and audit controls appropriate for production.
- No database, LLM credentials, Python implementation, login UI or automated test suite is bundled. Node does not store user documents or feedback.

## Smoke checks

```sh
curl -i http://127.0.0.1:3000/healthz
curl -i http://127.0.0.1:3000/api/sessions
curl -i -F "file=@sample.pdf" http://127.0.0.1:3000/api/sessions
```

Authenticated endpoints may correctly return 401 until you supply a valid session cookie or Authorization header. Verify browser upload, PDF preview, question/answer, feedback (including rejection of 6 without a comment), session restoration, and cross-user authorization against your Python service.

Generated source has not been npm-installed or executed against your backend in this environment. Generate and commit a package-lock.json after installation and validate dependencies, integration tests and deployment settings before release.
